# Orrery v0.9.1 Architectural & API Specification

- **Status:** Approved
- **Author:** Ritsuko Akagi (`ritsuko_architect`)
- **Date:** 2026-11-02
- **Target Release:** `v0.9.1`
- **Tracking Issues:** Refs #101, Refs #102, Refs #103, Part of #104
- **Affected Modules:** `orrery-core`, `orrery-compose`

---

## Overview & Goals

Orrery `v0.9.1` is a polish, ergonomics, and internationalization release building directly on the advanced layouts, hospitality ranges, collapsible scaffold, and schedule view introduced in `v0.9.0`.

It delivers three focused tracks without breaking binary or source compatibility:

1. **Animations & Smoothness (#101, `orrery-compose`):** Eliminates the visual alpha blink during `CollapsibleCalendarScaffold` collapse transitions, upgrades settle physics to velocity-aware springs, smooths day cell color/hover transitions, animates `WeekCalendar` height changes across `visibleWeeksCount` (`1..4`), and adds fluid zoom/layout/picker micro-animations.
2. **Booking Range Guardrails & Relative Navigation Helpers (#102, `orrery-core` & `orrery-compose`):** Enforces minimum nights, maximum nights, and non-passable disabled dates directly inside `SelectionEngine.clickRange`, `CalendarSelectionState`, and `OrreryDateRangePickerState`, alongside ergonomic next/previous navigation helpers on `CalendarState`, `WeekCalendarState`, and `ScheduleState`.
3. **Weekend Styling, Full RTL Mirroring & Keyboard Navigation Parity (#103, `orrery-compose`):** Adds first-class weekend tinting to headers and day cells, fixes custom canvas/layout mirroring under `LayoutDirection.Rtl`, and brings full keyboard navigation parity to `VerticalCalendar` and multi-row `WeekCalendar` (`TwoWeeks`).

### Explicit Non-Goals (Deliberately Out of Scope for v0.9.1)

- **Custom validation callbacks or async availability fetching in `SelectionEngine`:** Range guardrails are strictly synchronous predicates operating on `DisabledDates` and day counts (`minRangeDays`, `maxRangeDays`, `disallowDisabledInRange`).
- **Pinch-to-zoom gesture detector built into `ScheduleView`:** `v0.9.1` provides the programmatic `ScheduleState.animateHourHeightTo` suspend API; consumers bind their own gesture detectors or toolbar zoom controls.
- **Breaking existing binary signatures:** All modified composable entry points and data classes retain binary-compatible overloads or `@Deprecated(level = DeprecationLevel.HIDDEN)` bridges where needed.

## 1. Track #101 — Animations & Smoothness (`orrery-compose`)

### 1.1 `CollapsibleCalendarScaffold` Smooth Morph & Velocity-Aware Spring Settle

#### Problem
1. **Alpha blink near `expandFraction == 0f`:** Currently, `CollapsibleCalendarScaffold` applies `.graphicsLayer { alpha = (state.expandFraction / CollapsibleCalendarValue.TwoWeeks.expandFraction).coerceIn(0f, 1f) }` to the `HorizontalCalendar` layer while crossfading into `WeekCalendar`. As `expandFraction` approaches `0f` (`Week`), the entire month grid fades to `alpha = 0f` before swapping to `WeekCalendar`, causing a noticeable visual blink/dip in opacity on the active week row.
2. **Fixed-duration tween settle ignores gesture momentum:** `CollapsibleCalendarState.animateTo` uses `tween(durationMillis = 240)` and ignores drag/fling velocity, causing abrupt deceleration when flicking open or closed.

#### Specification
- **Eliminate the alpha fade on `HorizontalCalendar` during `1f -> 0f`:**
  - Keep `HorizontalCalendar` at `alpha = 1f` throughout the entire transition (`expandFraction in 0f..1f`).
  - Because `CollapsibleCalendarScaffold` already masks the container height via `Modifier.height(currentHeight).clipToBounds()` and translates the month grid vertically by `-anchorRowOffset * (1f - rowRevealProgress)`, non-anchor rows are naturally clipped while the active anchor week row remains aligned in place at full opacity.
  - Render `WeekCalendar` **only** when settled at `state.expandFraction == 0f` (and `!state.isDragging`), seamlessly swapping the single visible anchor row of `HorizontalCalendar` with the interactive `WeekCalendar` pager without any opacity dip.
- **Velocity-aware spring settle:**
  - Update `CollapsibleCalendarState.animateTo`:
    ```kotlin
    suspend fun animateTo(
        target: Float,
        initialVelocity: Float = 0f,
    )
    ```
  - Replace `tween(240)` with:
    ```kotlin
    spring(
        dampingRatio = Spring.DampingRatioNoBouncy,
        stiffness = Spring.StiffnessMediumLow,
    )
    ```
  - Pass `initialVelocity` (in `expandFraction` units per second) into `Animatable.animateTo(targetValue = coerced, animationSpec = ..., initialVelocity = initialVelocity)`.
  - In the scaffold's `draggable` (`onDragStopped`) and ` nestedScrollConnection.onPreFling`, convert pixel velocity (`px/s`) to fraction velocity (`fraction/s`) via `val fractionVelocity = velocityPxPerSec / maxCollapsePx` (accounting for drag direction sign) and pass it to `state.settle(initialVelocity = fractionVelocity)` / `state.animateTo(target.expandFraction, initialVelocity = fractionVelocity)`.

### 1.2 `DefaultDay` Smooth Color Transitions (`contentColor` & Hover Fill)

#### Problem
While `DefaultDay` animates `selectedScale` via a spring when `animateSelection = true`, `contentColor` and the pointer hover background alpha snap instantaneously, creating a visual mismatch between the scaling pill and the text/hover state.

#### Specification
- Inside `DefaultDay`:
  - Animate `contentColor` using `animateColorAsState`:
    ```kotlin
    val animatedContentColor by animateColorAsState(
        targetValue = targetContentColor,
        animationSpec = if (animateSelection) tween(durationMillis = 150) else snap(),
        label = "DefaultDayContentColor",
    )
    ```
  - Animate hover fill alpha using `animateFloatAsState`:
    ```kotlin
    val hoverAlpha by animateFloatAsState(
        targetValue = if (isHovered && !day.isDisabled && !day.isSelected) 1f else 0f,
        animationSpec = if (animateSelection) tween(durationMillis = 150) else snap(),
        label = "DefaultDayHoverAlpha",
    )
    ```
  - Apply `hoverAlpha` to the hover background draw pass and `animatedContentColor` to the day label composition local / text style.
  - When `animateSelection = false`, both transitions use `snap()` for deterministic immediate rendering in snapshot tests and reduced-motion configurations.

  ```kotlin
              day = day,

  ```

- When `animateHeight = true`, apply `Modifier.animateContentSize(animationSpec = spring(dampingRatio = Spring.DampingRatioNoBouncy, stiffness = Spring.StiffnessMediumLow))` (or animate the rows container height via `animateDpAsState`) so transitions between `visibleWeeksCount` (`1..4`) smoothly spring the container height.

## 2. Track #102 — Booking Range Guardrails & Relative Navigation Helpers (`orrery-core` & `orrery-compose`)

### 2.1 Booking Range Guardrails

#### Problem
Hospitality and booking calendars require three standard domain constraints during range selection:
1. Preventing a selected range from spanning across disabled/unavailable dates (e.g., an already booked night in the middle of a stay).
2. Enforcing a minimum stay length (`minRangeDays`, e.g., minimum 2 nights / 3 days).
3. Enforcing a maximum stay length (`maxRangeDays`, e.g., maximum 14 days).

#### Specification

1. **`SelectionEngine.clickRange` (`orrery-core`):**
   - Extend `SelectionEngine.clickRange` with default parameters and keep a binary-compatible 3-parameter overload:
     ```kotlin
     public fun clickRange(
         current: Selection.Range,
         date: LocalDate,
         disabled: DisabledDates = DisabledDates.None,
         disallowDisabledInRange: Boolean = false,
         minRangeDays: Int = 1,
         maxRangeDays: Int? = null,
     ): Selection.Range
     ```
   - Validation invariants:
     - `require(minRangeDays >= 1) { "minRangeDays must be >= 1, was $minRangeDays" }`
     - `require(maxRangeDays == null || maxRangeDays >= minRangeDays) { "maxRangeDays ($maxRangeDays) must be >= minRangeDays ($minRangeDays)" }`
   - Behavior when `current.start != null && current.end == null` and `date >= current.start` (second tap completing the range):
     - Let `daysCount = current.start.daysUntil(date) + 1` (inclusive day count; e.g., same-day `start == date` has `daysCount == 1`, overnight `start + 1 day` has `daysCount == 2`).
     - **Disabled date in range check:** If `disallowDisabledInRange == true` and any date `d` in `current.start..date` satisfies `disabled.isDisabled(d)`, **restart** the range at `date`: return `Selection.Range(start = date, end = null)`.
     - **Maximum range check:** If `maxRangeDays != null && daysCount > maxRangeDays`, **restart** the range at `date`: return `Selection.Range(start = date, end = null)`.
     - **Minimum range check:** If `daysCount < minRangeDays`, **ignore** the completing tap and keep the anchor: return `current` (`Selection.Range(start = current.start, end = null)`).
     - Otherwise, complete the range: return `Selection.Range(start = current.start, end = date)`.
   - Note: If `disabled.isDisabled(date)` is true for the tapped `date` itself, existing behavior remains unchanged (return `current` immediately).

2. **`CalendarSelectionState` & `rememberCalendarSelectionState` (`orrery-compose`):**
   - Add properties `disallowDisabledInRange: Boolean = false`, `minRangeDays: Int = 1`, and `maxRangeDays: Int? = null` to `CalendarSelectionState` and `rememberCalendarSelectionState`, forwarding them to `SelectionEngine.clickRange`.
   - Preserve binary compatibility for existing constructors and `rememberCalendarSelectionState` callers via default arguments / hidden bridge overloads.

3. **`OrreryDateRangePickerState` & `rememberOrreryDateRangePickerState` (`orrery-compose`):**
   - Add `disallowDisabledInRange: Boolean = false`, `minRangeDays: Int = 1`, and `maxRangeDays: Int? = null` to `OrreryDateRangePickerState` and `rememberOrreryDateRangePickerState`.
   - Enforce the same guardrails both when clicking dates in the calendar grid and when confirming manual text input in `DateInputMode.Input` (displaying an inline validation error if manual input violates `disallowDisabledInRange`, `minRangeDays`, or `maxRangeDays`).

### 2.2 Relative Navigation Helpers (`orrery-compose`)

#### Problem
Consumers building custom toolbar arrows or keyboard shortcuts currently have to compute `state.currentMonth.plusMonths(1)` or `state.firstVisibleDate.plus( state.visibleWeeksCount, DateTimeUnit.WEEK )` manually.

#### Specification

1. **`CalendarState`:**
   ```kotlin
   suspend fun animateScrollToNextMonth() = animateScrollToMonth(currentMonth.plusMonths(1))
   suspend fun animateScrollToPreviousMonth() = animateScrollToMonth(currentMonth.minusMonths(1))
   suspend fun scrollToNextMonth() = scrollToMonth(currentMonth.plusMonths(1))
   suspend fun scrollToPreviousMonth() = scrollToMonth(currentMonth.minusMonths(1))
   ```
   *(All operations naturally clamp to `startMonth..endMonth` via existing `scrollToMonth` / `animateScrollToMonth` bounds clamping.)*

2. **`WeekCalendarState`:**
   *(Steps by `visibleWeeksCount` weeks per page so multi-week views advance by a full visible page.)*
   ```kotlin
   suspend fun animateScrollToNextWeek() =
       animateScrollToWeek(currentWeekStart.plus(visibleWeeksCount, DateTimeUnit.WEEK))
   suspend fun animateScrollToPreviousWeek() =
       animateScrollToWeek(currentWeekStart.minus(visibleWeeksCount, DateTimeUnit.WEEK))
   suspend fun scrollToNextWeek() =
       scrollToWeek(currentWeekStart.plus(visibleWeeksCount, DateTimeUnit.WEEK))
   suspend fun scrollToPreviousWeek() =
       scrollToWeek(currentWeekStart.minus(visibleWeeksCount, DateTimeUnit.WEEK))
   ```

3. **`ScheduleState`:**
   *(Provides both page-stepped helpers advancing by `daysVisible` and single-day helpers advancing by `1` day.)*
   ```kotlin
   suspend fun animateScrollToNextPage() =
       animateScrollToDate(currentDate.plus(daysVisible, DateTimeUnit.DAY))
   suspend fun animateScrollToPreviousPage() =
       animateScrollToDate(currentDate.minus(daysVisible, DateTimeUnit.DAY))
   suspend fun scrollToNextPage() =
       scrollToDate(currentDate.plus(daysVisible, DateTimeUnit.DAY))
   suspend fun scrollToPreviousPage() =
       scrollToDate(currentDate.minus(daysVisible, DateTimeUnit.DAY))
   suspend fun animateScrollToNextDay() =
       animateScrollToDate(currentDate.plus(1, DateTimeUnit.DAY))
   suspend fun animateScrollToPreviousDay() =
       animateScrollToDate(currentDate.minus(1, DateTimeUnit.DAY))
   ```

2. **`CalendarDayColors` & `CalendarDefaults.dayColors`:**
   - Add `weekendDays: Set<DayOfWeek> = setOf(DayOfWeek.SATURDAY, DayOfWeek.SUNDAY)` and `weekendContentColor: Color = contentColor` to `CalendarDayColors` and `CalendarDefaults.dayColors(...)` (keeping binary-compatible constructors/functions):

     ```kotlin
     @Immutable
     ```

### 3.2 Full RTL (`LayoutDirection.Rtl`) Mirroring

#### Problem
Standard Compose layouts (`Row`, `HorizontalPager`) automatically mirror under `CompositionLocalProvider(LocalLayoutDirection provides LayoutDirection.Rtl)`, but custom `Canvas` drawing and custom `Layout` coordinate placement in three components currently assume left-to-right (`Ltr`) geometry.

#### Specification

1. **`WeekEventBanners` Custom `Layout` & Corner Radii:**
   - In the custom `Layout` measurement/placement block, compute the horizontal column start offset using `layoutDirection`:
     ```kotlin
     val visualStartCol = if (layoutDirection == LayoutDirection.Rtl) {
         totalCols - segment.endColExclusive
     } else {
         segment.startCol
     }
     val xOffset = (visualStartCol * colWidthPx).roundToInt()
     ```
   - When constructing the banner background `RoundedCornerShape`, use logical `topStart` / `bottomStart` (for `!segment.continuesFromPreviousWeek`) and `topEnd` / `bottomEnd` (for `!segment.continuesIntoNextWeek`) so Compose automatically mirrors the rounded vs. flat continuation edges in RTL, or explicitly swap left/right radii when drawing on `Canvas`.

2. **`DefaultDay` `drawRangeBand` & `drawSplitEndpoint` (`SplitHorizontal` & `SplitDiagonal`):**
   - **`drawRangeBand`:**
     - In `Ltr`, `RangeStart` fills the right half `[width / 2f, width]` and `RangeEnd` fills the left half `[0f, width / 2f]`.
     - In `Rtl`, mirror the half-bands: `RangeStart` fills the left half `[0f, width / 2f]` (pointing toward later days on the left), and `RangeEnd` fills the right half `[width / 2f, width]` (connecting from earlier days on the right).
   - **`drawSplitEndpoint`:**
     - **`RangeStyle.SplitHorizontal`:** In `Ltr`, check-out (`RangeEnd`) occupies the left half and check-in (`RangeStart`) occupies the right half. In `Rtl`, mirror horizontally so check-out (`RangeEnd`) occupies the right half and check-in (`RangeStart`) occupies the left half.
     - **`RangeStyle.SplitDiagonal`:** Mirror the diagonal slash line and triangle clipping vertices horizontally (`x' = size.width - x`) when `layoutDirection == LayoutDirection.Rtl`, so the AM/check-out half sits on the top-right (connecting to the right) and the PM/check-in half sits on the bottom-left (connecting to the left).

3. **`ScheduleView` `EventOverlapMode.Stacked` Horizontal Indent:**
   - When `overlapMode == EventOverlapMode.Stacked`, overlapping events are indented by `stackIndex * indentFraction`.
   - Under `LayoutDirection.Rtl`, mirror the horizontal placement within the day column so stacked cards indent from the right (start) edge toward the left (end) edge:
     ```kotlin
     val xPx = if (layoutDirection == LayoutDirection.Rtl) {
         ((1f - animatedLeftFraction - animatedWidthFraction) * columnWidthPx).roundToInt()
     } else {
         (animatedLeftFraction * columnWidthPx).roundToInt()
     }
     ```

### 3.3 `VerticalCalendar` & `WeekCalendar` (`TwoWeeks`) Keyboard Navigation Parity

#### Problem
`HorizontalCalendar` and single-row `WeekCalendar` support keyboard navigation, but `VerticalCalendar` and multi-row `WeekCalendar` (`visibleWeeksCount > 1`) either lack `keyboardNavigation` support or do not traverse multi-week rows and month boundaries consistently.

#### Specification
- Add `keyboardNavigation: Boolean = true` to `VerticalCalendar` (with binary-compatible overloads) and ensure `WeekCalendar`'s `keyboardNavigation: Boolean = true` works across all `visibleWeeksCount in 1..4`.
- Key bindings when focused:
  - `DirectionLeft` / `DirectionRight`: Move focus by `-1` / `+1` day in `Ltr`, or `+1` / `-1` day in `Rtl` (mirroring directional arrow keys under `LayoutDirection.Rtl`).
  - `DirectionUp` / `DirectionDown`: Move focus by `-7` / `+7` days (one week row up/down).
  - `MoveHome` / `MoveEnd`: Jump to the start / end of the current week row (or start/end of month in `VerticalCalendar` when `Ctrl`/`Meta` is held).
  - `PageUp` / `PageDown`:
    - In `VerticalCalendar`: Jump by `-1` / `+1` month and scroll the `LazyListState` so the target month is visible.
    - In `WeekCalendar`: Jump by `-visibleWeeksCount` / `+visibleWeeksCount` weeks and scroll the week pager to the target page.
  - `Enter` / `NumPadEnter` / `Spacebar`: Invoke `onDateClick(focusedDate)` if `!disabledDates.isDisabled(focusedDate)`.

## 4. Approved Design Decisions

All three design decisions (Q1, Q2, and Q3) have been approved by Andrii and are final for `v0.9.1`:

1. **Q1: `minRangeDays` / `maxRangeDays` Unit — Inclusive Calendar Days (Approved & Final)**
   - *Context:* Hospitality apps often think in "nights" (`end - start`), whereas general date-range pickers count inclusive calendar days (`end - start + 1`, where a single-day range `start == end` is `1` day).
   - *Decision:* **Count inclusive calendar days (`daysBetween + 1`, default `minRangeDays = 1`)**. This keeps `minRangeDays = 1` backward-compatible with same-day range completion (`Selection.Range(d, d)`). A 1-night minimum stay is expressed as `minRangeDays = 2`.

2. **Q2: `minRangeDays` Violation Behavior on Second Tap — Ignore vs. Restart (Approved & Final)**
   - *Context:* When a user has selected `start = Nov 10` with `minRangeDays = 3` and taps `Nov 11` (2 days), should the tap be ignored (keeping `Selection.Range(Nov 10, null)`) or restart the anchor at `Nov 11`?
   - *Decision:* **Ignore the tap and keep `Selection.Range(start, null)`** for `minRangeDays` violations (as specified in #102), while **restarting at `Selection.Range(date, null)`** when `disallowDisabledInRange` or `maxRangeDays` is violated. Ignoring short taps prevents accidental anchor resets when a user accidentally double-taps the start date or taps one day too close.

3. **Q3: Left/Right Arrow Key Direction Under `LayoutDirection.Rtl` (Approved & Final)**
   - *Context:* In RTL layouts, the visual grid flows right-to-left (Sunday on the right, Saturday on the left).
   - *Decision:* **Mirror `DirectionLeft` (`+1` day) and `DirectionRight` (`-1` day) in RTL** to match visual grid flow, so `DirectionLeft` advances to `focusedDate + 1 day` (visually leftward) and `DirectionRight` moves to `focusedDate - 1 day` (visually rightward), matching spatial arrow-key expectations in WAI-ARIA and Material 3.
