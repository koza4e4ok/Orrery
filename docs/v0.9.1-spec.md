# Orrery v0.9.1 Architectural & API Specification

- **Status:** Approved
- **Author:** Ritsuko Akagi (`ritsuko_architect`)
- **Date:** 2026-11-03
- **Target Release:** `v0.9.1`
- **Tracking Issues:** Refs #101, Refs #102, Refs #103, Part of #104
- **Affected Modules:** `orrery-core`, `orrery-compose`

---

## Overview & Goals

Orrery `v0.9.1` is a polish, ergonomics, and internationalization release building directly on the advanced layouts, hospitality ranges, collapsible scaffold, and schedule view introduced in `v0.9.0`.

It delivers three focused tracks without breaking binary or source compatibility:

1. **Animations & Smoothness (#101, `orrery-compose`):** Eliminates the visual alpha blink during `CollapsibleCalendarScaffold` collapse transitions, upgrades settle physics to velocity-aware springs, smooths day cell color/hover transitions, animates `WeekCalendar` height changes across `visibleWeeksCount` (`1..4`), and adds fluid programmatic zoom, overlap placement, picker headline, and header chevron micro-animations.
2. **Booking Range Guardrails & Relative Navigation Helpers (#102, `orrery-core` & `orrery-compose`):** Enforces minimum stay days, maximum stay days, and non-passable disabled dates directly inside `SelectionEngine`, `CalendarSelectionState`, and `OrreryDateRangePickerState`, alongside ergonomic next/previous navigation helpers on `CalendarState`, `WeekCalendarState`, and `ScheduleState`.
3. **Weekend Styling, Full RTL Mirroring & Keyboard Navigation Parity (#103, `orrery-compose`):** Adds first-class weekend tinting to weekday headers and day cells, exposes testable RTL geometry helpers and RTL schedule grid-line alignment under `LayoutDirection.Rtl`, and brings full keyboard navigation parity to `VerticalCalendar` and multi-row `WeekCalendar` (`TwoWeeks`).

### Explicit Non-Goals (Deliberately Out of Scope for v0.9.1)

- **Custom validation callbacks or async availability fetching in `SelectionEngine`:** Range guardrails are strictly synchronous predicates operating on `DisabledDates` and inclusive day counts (`minRangeDays`, `maxRangeDays`, `disallowDisabledInRange`).
- **Replacing `ScheduleView`'s existing touch pinch-to-zoom gesture detector:** `ScheduleView` already provides built-in touch pinch-to-zoom via `Modifier.pinchToZoomHours(state, options.zoomGesturesEnabled)`; `v0.9.1` complements it with the programmatic `ScheduleState.animateHourHeightTo` suspend API for toolbar zoom controls and double-tap/shortcut zoom animations.
- **Breaking existing binary signatures:** All modified composable entry points and classes retain binary-compatible overloads or `@Deprecated(level = DeprecationLevel.HIDDEN)` bridges where needed.

## 1. Track #101 — Animations & Smoothness (`orrery-compose`)

### 1.1 `CollapsibleCalendarScaffold` Smooth Morph & Velocity-Aware Spring Settle

#### Problem
1. **Alpha blink near `expandFraction == 0f`:** Previously, `CollapsibleCalendarScaffold` crossfaded `HorizontalCalendar` and `WeekCalendar` around `CollapsibleCalendarAnchor.TwoWeeks.expandFraction` (`0.35f`), fading the month grid toward `alpha = 0f` before swapping to `WeekCalendar` and causing a visible opacity dip on the active week row.
2. **Fixed-duration tween settle ignores gesture momentum:** `CollapsibleCalendarState.animateTo` used `tween(durationMillis = 240)` and ignored drag/fling velocity, causing abrupt deceleration when flicking open or closed.

#### Specification
- **Eliminate the alpha fade on `HorizontalCalendar` during `1f -> 0f`:**
  - Keep `HorizontalCalendar` at `alpha = 1f` throughout `expandFraction > 0f` (`monthGridAlpha(expandFraction) = if (expandFraction <= 0f) 0f else 1f`).
  - Because `CollapsibleCalendarScaffold` masks the container height via `Modifier.height(currentHeight).clipToBounds()` (interpolated across `CollapsibleGeometry`'s piecewise spans `minHeight..midHeight` for `0f..0.35f` and `midHeight..maxHeight` for `0.35f..1f`) and translates the month grid vertically by `-anchorRowOffset * (1f - rowRevealProgress)`, non-anchor rows are naturally clipped while the active anchor week row remains aligned in place at full opacity.
  - Render `WeekCalendar` at full opacity **only** when settled at `state.expandFraction <= 0f` (`weekRowAlpha(expandFraction) = if (expandFraction <= 0f) 1f else 0f`), seamlessly swapping the single visible anchor row of `HorizontalCalendar` with the interactive `WeekCalendar` pager without any opacity dip.
- **Velocity-aware spring settle:**
  - Update `CollapsibleCalendarState.animateTo` (retaining a binary-compatible single-argument overload):
    ```kotlin
    public suspend fun animateTo(
        target: CollapsibleCalendarAnchor,
        initialVelocity: Float = 0f,
    )
    ```
  - Replace `tween(240)` with:
    ```kotlin
    spring(
        dampingRatio = Spring.DampingRatioNoBouncy,
        stiffness = Spring.StiffnessMediumLow,
    )
    ```
  - Pass `initialVelocity` (in `expandFraction` units per second) into `Animatable.animateTo(targetValue = target.expandFraction, animationSpec = ..., initialVelocity = initialVelocity)`.
  - In the scaffold's `draggable` (`onDragStopped`) and `nestedScrollConnection.onPreFling`, resolve the target anchor via `state.settleTarget(velocity, thresholdPx)`, convert pixel velocity (`px/s`) to fraction velocity (`fraction/s`) across the active `CollapsibleGeometry` span, and pass `initialVelocity = fractionVelocity` to `state.animateTo(target, initialVelocity = fractionVelocity)`.

### 1.2 `DefaultDay` Smooth Color Transitions (`contentColor` & Hover Fill)

#### Problem
While `DefaultDay` animates `selectedScale` via a spring when `animateSelection = true`, `contentColor` and the pointer hover background alpha previously snapped instantaneously, creating a visual mismatch between the scaling pill and the text/hover state.

#### Specification
- Inside `DefaultDay`:
  - Animate `contentColor` using `animateColorAsState`:
    ```kotlin
    val contentColor by animateColorAsState(
        targetValue = targetContentColor,
        animationSpec = if (animateSelection) tween(durationMillis = 150) else snap(),
        label = "dayContentColor",
    )
    ```
  - Animate hover fill alpha using `animateFloatAsState`:
    ```kotlin
    val hoverAlpha by animateFloatAsState(
        targetValue = if (isHovered && available && !isSelected && !splitEndpoint && !isTurnover) 1f else 0f,
        animationSpec = if (animateSelection) tween(durationMillis = 150) else snap(),
        label = "dayHoverAlpha",
    )
    ```
  - Apply `hoverAlpha` to the `colors.hoverContainerColor` draw pass and `contentColor` to the day label composition local / text rendering.
  - When `animateSelection = false`, both transitions use `snap()` for deterministic immediate rendering in snapshot tests and reduced-motion configurations.

#### Problem
Changing `WeekCalendar`'s `visibleWeeksCount` dynamically (e.g., toggling between `1` week and `2` weeks) caused the `WeekCalendar` container height to jump abruptly.

#### Specification
- Add `animateHeight: Boolean = true` to both slot-based `WeekCalendar` overloads (raw `WeekCalendarState` and `CalendarSelectionState`) while preserving binary-compatible `@Deprecated(level = DeprecationLevel.HIDDEN)` bridges:

  ```kotlin
          CalendarDefaults.Day(day)
      },

  ```
- When `animateHeight = true`, `WeekCalendarContent` tracks the measured page height in pixels and animates height changes via `Animatable(Float.NaN)` with `spring(dampingRatio = Spring.DampingRatioNoBouncy, stiffness = Spring.StiffnessMediumLow)` and `Modifier.height(...).clipToBounds()`, smoothly springing between `visibleWeeksCount` (`1..4`).

### 1.4 `ScheduleView` Animated Zoom & Event Placement + Picker/Header Micro-Animations

#### Specification

1. **`ScheduleState.animateHourHeightTo`:**
   - Add a suspend function to `ScheduleState`:
     ```kotlin
     public suspend fun animateHourHeightTo(
         target: Dp,
         animationSpec: AnimationSpec<Dp> = spring(stiffness = Spring.StiffnessMediumLow),
     )
     ```
   - Coerces `target` within `minHourHeight..maxHourHeight` (default `36.dp..160.dp`), animates `hourHeight` smoothly using `animate(initialValue = hourHeight, targetValue = clamped, typeConverter = Dp.VectorConverter, animationSpec = animationSpec)`, and proportionally scales `verticalScrollState` so the top visible time anchor remains stable during zoom.

2. **`ScheduleView` Timed Event Tile Horizontal Placement Animation:**

3. **Picker Headline Directional Slide + Fade (`OrreryDatePickerDialog` & `OrreryDateRangePickerDialog`):**

4. **`CalendarNavHeader` `DropdownTriangle` Rotation:**
   - Add `expanded: Boolean = false` to `CalendarNavHeader` (retaining a binary-compatible `@Deprecated(level = DeprecationLevel.HIDDEN)` bridge):

## 2. Track #102 — Booking Range Guardrails & Relative Navigation Helpers (`orrery-core` & `orrery-compose`)

### 2.1 Booking Range Guardrails

#### Problem
Hospitality and booking calendars require three standard domain constraints during range selection:
1. Preventing a selected range from spanning across disabled/unavailable dates (e.g., an already booked night in the middle of a stay).
2. Enforcing a minimum stay length (`minRangeDays`, e.g., minimum 2 nights / 3 inclusive calendar days).
3. Enforcing a maximum stay length (`maxRangeDays`, e.g., maximum 14 inclusive calendar days).

#### Specification

1. **`SelectionEngine` (`orrery-core`):**
   - Extend `SelectionEngine`'s primary constructor with default parameters and keep a binary-compatible 3-parameter secondary constructor:
     ```kotlin
     public class SelectionEngine(
         public val mode: SelectionMode,
         public val bounds: DateRange? = null,
         public val disabled: DisabledDates = DisabledDates.None,
         public val disallowDisabledInRange: Boolean = false,
         public val minRangeDays: Int = 1,
         public val maxRangeDays: Int? = null,
     )
     ```
   - Validation invariants in `init`:
     - `require(minRangeDays >= 1) { "minRangeDays must be at least 1, got $minRangeDays" }`
     - `require(maxRangeDays == null || maxRangeDays >= minRangeDays) { "maxRangeDays ($maxRangeDays) must be >= minRangeDays ($minRangeDays)" }`
   - Behavior in `clickRange(current: Selection, date: LocalDate): SelectionResult` when `current.rangeStart != null && current.rangeEnd == null` and `date >= current.rangeStart` (second tap completing the range):
     - Let `daysCount = current.rangeStart.daysUntil(date) + 1` (inclusive day count; e.g., same-day `start == date` has `daysCount == 1`, overnight `start + 1 day` has `daysCount == 2`).
     - **Disabled date in range check:** If `disallowDisabledInRange == true` and any date `d` in `current.rangeStart..date` satisfies `d in disabled`, **restart** the range at `date`: return `Selection(rangeStart = date)` with `SelectionEvent.RangeStarted(date)`.
     - **Maximum range check:** If `maxRangeDays != null && daysCount > maxRangeDays`, **restart** the range at `date`: return `Selection(rangeStart = date)` with `SelectionEvent.RangeStarted(date)`.
     - **Minimum range check:** If `daysCount < minRangeDays`, **ignore** the completing tap and keep the anchor: return `current` (`Selection(rangeStart = current.rangeStart)`) with `SelectionEvent.Intercepted(date, SelectionRejection.RangeTooShort(minRangeDays))`.
     - Otherwise, complete the range: return `Selection(rangeStart = current.rangeStart, rangeEnd = date)` with `SelectionEvent.RangeCompleted(DateRange(current.rangeStart, date))`.
   - Consistency across `replace(range: DateRange)`, `dragEnd`, and `extendRange`:
     - Enforce `minRangeDays`, `maxRangeDays`, and `disallowDisabledInRange` consistently across programmatic/input range replacement (`SelectionEngine.replace`) and drag/keyboard range extension (`CalendarSelectionState`).

2. **`CalendarSelectionState` & `rememberCalendarSelectionState` (`orrery-compose`):**
   - Add `disallowDisabledInRange: Boolean = false`, `minRangeDays: Int = 1`, and `maxRangeDays: Int? = null` to `CalendarSelectionState` and `rememberCalendarSelectionState`, forwarding them to `SelectionEngine`.
   - Preserve binary compatibility for existing constructors and `rememberCalendarSelectionState` callers via default arguments and `@Deprecated(level = DeprecationLevel.HIDDEN)` bridge overloads.

3. **`OrreryDateRangePickerState` & `rememberOrreryDateRangePickerState` (`orrery-compose`):**
   - Add `disallowDisabledInRange: Boolean = false`, `minRangeDays: Int = 1`, and `maxRangeDays: Int? = null` to `OrreryDateRangePickerState` and `rememberOrreryDateRangePickerState` (alongside existing `minDays` / `maxDays` support).
   - Enforce the guardrails both when clicking dates in the calendar grid and when confirming manual text input in `DatePickerDisplayMode.Input` / `setSelection`.

### 2.2 Relative Navigation Helpers (`orrery-compose`)

#### Problem
Consumers building custom toolbar arrows or keyboard shortcuts previously had to compute target months, multi-week offsets, or schedule page offsets manually.

#### Specification

1. **`CalendarState`:**
   ```kotlin
   public suspend fun animateScrollToNextMonth() =
       animateScrollToMonth(CalendarPages.monthAt(firstVisibleMonth, 1))
   public suspend fun animateScrollToPreviousMonth() =
       animateScrollToMonth(CalendarPages.monthAt(firstVisibleMonth, -1))
   public suspend fun scrollToNextMonth() =
       scrollToMonth(CalendarPages.monthAt(firstVisibleMonth, 1))
   public suspend fun scrollToPreviousMonth() =
       scrollToMonth(CalendarPages.monthAt(firstVisibleMonth, -1))
   ```
   *(All operations naturally clamp to `startMonth..endMonth` via `scrollToMonth` / `animateScrollToMonth`.)*

2. **`WeekCalendarState`:**
   *(Steps by `visibleWeeksCount` weeks per page so multi-week views advance by a full visible page, clamped to `startDate..endDate`.)*
   ```kotlin
   public suspend fun animateScrollToNextWeek()
   public suspend fun animateScrollToPreviousWeek()
   public suspend fun scrollToNextWeek()
   public suspend fun scrollToPreviousWeek()
   ```

3. **`ScheduleState`:**
   *(Provides both page-stepped helpers advancing by `paging.pages.daysPerPage` when attached to `DaySchedule`/`WeekSchedule`—or `1` day when detached—and single-day helpers advancing by `1` day, all clamped to `startDate..endDate`.)*
   ```kotlin
   public suspend fun animateScrollToNextPage()
   public suspend fun animateScrollToPreviousPage()
   public suspend fun scrollToNextPage()
   public suspend fun scrollToPreviousPage()
   public suspend fun animateScrollToNextDay()
   public suspend fun animateScrollToPreviousDay()
   public suspend fun scrollToNextDay()
   public suspend fun scrollToPreviousDay()
   ```

### 3.2 Full RTL (`LayoutDirection.Rtl`) Mirroring

#### Baseline & Problem
Compose's `placeRelative` in `WeekEventBanners` (combined with logical `RoundedCornerShape(topStart, topEnd, bottomEnd, bottomStart)`) and in `ScheduleView`'s `DayColumn` already mirrors horizontal placement automatically under `LayoutDirection.Rtl`. The remaining RTL work covers testable `DefaultDay` canvas geometry helpers and `ScheduleView` vertical grid-line dividers:

#### Specification

1. **`WeekEventBanners` & `ScheduleView` `DayColumn` (`placeRelative`):**
   - Keep logical start coordinates inside `WeekEventBanners` and `ScheduleView` `DayColumn` so `placeable.placeRelative(x, y)` mirrors spans and stacked overlap offsets once without double-mirroring.
   - In `ScheduleView` (`Modifier.gridLines`), mirror vertical day-column divider lines when `layoutDirection == LayoutDirection.Rtl` (`day in 1..dayCount` instead of `0 until dayCount`) so the border sits between `HourGutter` (on the right in RTL) and the first day column rather than on the outer left screen edge.

2. **`DefaultDay` `drawRangeBand` & `drawSplitEndpoint` (`RangeEndpointStyle.SplitHorizontal` & `RangeEndpointStyle.SplitDiagonal`):**
   - Extract deterministic geometry helpers `rangeBandHalfBounds(width, isStart, isEnd, isRtl)` and `splitEndpointPolygons(width, height, diagonal, isRtl)`:
     - **`drawRangeBand`:** In `Ltr`, `isStart` fills `[width / 2f, width]` and `isEnd` fills `[0f, width / 2f]`. In `Rtl`, mirror the half-bands so `isStart` fills `[0f, width / 2f]` and `isEnd` fills `[width / 2f, width]`.
     - **`RangeEndpointStyle.SplitHorizontal`:** In `Ltr`, check-out (`endHalf`) occupies the left half and check-in (`startHalf`) occupies the right half; in `Rtl`, mirror horizontally so check-out occupies the right half and check-in occupies the left half.
     - **`RangeEndpointStyle.SplitDiagonal`:** Mirror the diagonal slash vertices horizontally (`x' = width - x`) when `isRtl == true`.

### 3.3 `VerticalCalendar` & `WeekCalendar` (`TwoWeeks`) Keyboard Navigation Parity

#### Problem
`HorizontalCalendar` and single-row `WeekCalendar` supported keyboard navigation, whereas `VerticalCalendar` lacked `keyboardNavigation` parameters and directional arrow keys did not invert under `LayoutDirection.Rtl`.

#### Specification
- Add `keyboardNavigation: Boolean = false` to both `VerticalCalendar` overloads (raw `CalendarState` and `CalendarSelectionState`, retaining binary-compatible `@Deprecated(level = DeprecationLevel.HIDDEN)` bridges) and support `WeekCalendar`'s `keyboardNavigation` across `visibleWeeksCount in 1..4`.
- Key bindings when focused:
  - `DirectionLeft` / `DirectionRight`: Move focus by `-1` / `+1` day in `Ltr`, or `+1` / `-1` day in `Rtl` via `horizontalArrowDayOffset(isRightKey, isRtl)`.
  - `DirectionUp` / `DirectionDown`: Move focus by `-7` / `+7` days (one week row up/down).
  - `MoveHome` / `MoveEnd`: Jump to the start / end of the current week row (or start/end of the month when `Ctrl`/`Meta` is held).
  - `PageUp` / `PageDown`: Jump by `-1` / `+1` month across `HorizontalCalendar`, `VerticalCalendar`, and `WeekCalendar` (with `Shift+PageUp` / `Shift+PageDown` jumping by `-1` / `+1` year), scrolling the underlying month list/pager or week pager so the target date is visible in the viewport.
  - `Enter` / `NumPadEnter` / `Spacebar`: Invoke date selection on the focused date if enabled.

## 4. Approved Design Decisions

All three design decisions (Q1, Q2, and Q3) have been approved by Andrii and are final for `v0.9.1`:

1. **Q1: `minRangeDays` / `maxRangeDays` Unit — Inclusive Calendar Days (Approved & Final)**
   - *Context:* Hospitality apps often think in "nights" (`end - start`), whereas general date-range pickers count inclusive calendar days (`end - start + 1`, where a single-day range `start == end` is `1` day).
   - *Decision:* **Count inclusive calendar days (`daysBetween + 1`, default `minRangeDays = 1`)**. This keeps `minRangeDays = 1` backward-compatible with same-day range completion (`Selection(rangeStart = d, rangeEnd = d)`). A 1-night minimum stay is expressed as `minRangeDays = 2`.

2. **Q2: `minRangeDays` Violation Behavior on Second Tap — Ignore vs. Restart (Approved & Final)**
   - *Context:* When a user has selected `start = Nov 10` with `minRangeDays = 3` and taps `Nov 11` (2 days), should the tap be ignored (keeping `Selection(rangeStart = Nov 10)`) or restart the anchor at `Nov 11`?
   - *Decision:* **Ignore the tap and keep `Selection(rangeStart = start)`** for `minRangeDays` violations (as specified in #102), while **restarting at `Selection(rangeStart = date)`** when `disallowDisabledInRange` or `maxRangeDays` is violated. Ignoring short taps prevents accidental anchor resets when a user accidentally double-taps the start date or taps one day too close.

3. **Q3: Left/Right Arrow Key Direction Under `LayoutDirection.Rtl` (Approved & Final)**
   - *Context:* In RTL layouts, the visual grid flows right-to-left (first day of week on the right, last day of week on the left).
   - *Decision:* **Mirror `DirectionLeft` (`+1` day) and `DirectionRight` (`-1` day) in RTL** to match visual grid flow, so `DirectionLeft` advances to `focusedDate + 1 day` (visually leftward) and `DirectionRight` moves to `focusedDate - 1 day` (visually rightward), matching spatial arrow-key expectations in WAI-ARIA and Material 3.
